# GitPush

一键完成 `git add .` → `git commit -m "<自动生成的提交信息>"` → `git push`，提交信息根据代码变更自动生成中文描述。**所有操作由 AI 直接执行。**

## 执行步骤

按顺序完成：

### 1. 检查变更

执行以下命令检查工作区状态：

```bash
git status --porcelain
```

- 若无任何输出（工作区干净）→ 告知用户"没有需要提交的变更"，流程结束
- 若有变更 → 继续下一步

### 2. 展示变更并确认

执行以下命令展示变更摘要：

```bash
git diff --stat
git diff --stat --cached
```

向用户展示待提交的文件变更摘要（新增/修改/删除的文件列表及行数变化）：

```
📊 变更摘要：
{git diff --stat 的输出}

{git diff --stat --cached 的输出}

是否继续提交？(Y/n)
```

- 若用户确认（默认 Y）→ 继续
- 若用户取消 → 流程结束
- 若对话上下文中用户已明确表示要提交（如"帮我推送一下"），可跳过此确认步骤直接执行

### 3. 暂存所有变更

```bash
git add .
```

执行后检查是否有报错。若 `git add .` 失败（如文件锁、权限问题），提示错误并结束流程。

### 4. 生成提交信息并提交

分析 `git diff --cached` 的变更内容和当前对话上下文，提炼一句**简洁、准确的中文提交信息**（≤50 字）：

**提交信息规范**：
- 使用 `<type>: <description>` 格式，如 `feat: 新增用户注册接口`、`fix: 修复空指针异常`、`refactor: 重构订单查询逻辑`
- type 参考常用约定：feat / fix / refactor / chore / docs / style / perf / test / ci
- description 用中文，准确反映变更核心
- 不写句号结尾

执行：

```bash
git commit -m "<生成的提交信息>"
```

- 若提交成功 → 继续下一步
- 若提交失败（如 GPG 签名问题、hooks 报错）→ 展示错误信息，询问用户如何处理

### 5. 推送到远端

```bash
git push
```

- 若推送成功 → 展示提交信息摘要：

```

✅ 已推送完成

提交: <commit hash> - <提交信息>
分支: <当前分支名> → origin/<当前分支名>
变更: {X} 个文件，{Y} 行变更
```

- 若推送失败（如远程被更新、网络问题）：
  - 若是非快进问题 → 提示用户冲突，建议先 `git pull --rebase` 再推送
  - 若是网络/认证问题 → 提示用户检查网络和认证状态

## 异常处理

| 情况 | 处理方式 |
|------|---------|
| 工作区干净 | 告知用户"没有需要提交的变更"，流程结束 |
| git add 失败 | 提示错误信息，结束流程 |
| git commit 失败 | 展示错误详情，询问用户是否重试或手动提交 |
| git push 非快进拒绝 | 提示远程有更新，建议 `git pull --rebase` 解决冲突 |
| git push 网络/认证失败 | 提示用户检查网络连接和 Git 认证配置 |
| 用户中途取消 | 流程结束，不遗留未完成的操作 |
