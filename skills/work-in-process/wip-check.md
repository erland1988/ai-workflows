# wip-check

编码前**一次性全量检查**——校验设计方案自洽性 + 执行计划完整性。不再分两次执行。

> ⚠️ **只做检查和输出报告，禁止修改源码。** 发现问题需回退 wip-build 修正设计/计划后重新检查，通过前禁止进入 wip-code。

## 检查项

1. **需求覆盖检查**：
   - 需求背景中的每条要点在设计文档中是否有对应？
   - 范围边界是否清晰？

2. **模块划分合理性**：
   - 各模块边界是否清晰，有无职责重叠？
   - 模块间接口契约是否完整定义？
   - 前置/后置依赖关系是否形成环？

3. **执行计划完整性**：
   - 是否按依赖顺序分阶段？
   - 每个步骤是否齐备「文件/位置/背景/操作/验证」？
   - 测试矩阵是否覆盖正常流、边界、幂等、并发？

4. **design ↔ plan 一致性**：
   - plan 的变更文件与 design 的变更文件汇总是否一致？
   - plan 的 Phase 划分是否覆盖 design 的所有模块？

5. **ledger 一致性**：
   - 文档中标记已完成的阶段与 ledger 记录是否一致？

## 输出

问题清单（如有），无问题则标记 `wip-check` 通过，**自动更新 ledger.md**：
- 各模块 `检查` 列标记为 ✅（或 ❌ 待修复）
- 当前阶段更新为 `check`

## 通过标准

无阻塞性问题，可进入编码。wip-check 通过后 ledger 自动更新。

## 不通过处理

检查不通过（存在阻塞性问题）：

1. 更新 ledger：各模块 `检查` 列标记 ❌，当前阶段保持 `design` / `check`
2. **回到 wip-build 重新产出** design.md / plan.md（覆盖式修正）
3. 重新执行 wip-check，直到通过

> ⚠️ **未通过前禁止进入 wip-code。**
>
> 已进入 wip-code 后才发现需求偏差多、需回退重新设计时,使用 `wip-rollback`(清理残留 worktree + 丢弃已合并代码 + 重置 ledger)回到设计阶段,再走 wip-build → wip-check → wip-code。
