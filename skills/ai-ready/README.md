# AIReady

把项目改造成「AI 开箱能接手」的状态：调研代码 → 生成架构与接口文档 → 接入 comate → 编写 AGENTS.md → 补 README。

## 快速开始

```
ai-ready           # 对当前项目执行完整改造
```

## 阶段

```
阶段 0  调研（不可跳）      摸清事实，每条结论落到 文件:行
  ↓
阶段 1  架构文档            docs/architecture/backend-architecture.md
  ↓
阶段 2  接口文档            docs/architecture/api-contract.md
  ↓
阶段 3  接入 comate         openspec/ + docs/ 骨架（团队使用时）
  ↓
阶段 4  AGENTS.md ⭐        让 AI 自动接手的关键
  ↓
阶段 5  README              环境地址 / 本地开发 / AI 协作
```

## 三条铁律

| # | 铁律 | 为什么 |
|---|------|--------|
| 1 | 每条约束标注**实测出处**（`文件:行`） | 未经验证的推断写进去，比不写更误导 |
| 2 | **索引式**，不复制内容 | 复制必然不同步，单一事实源会被撕裂 |
| 3 | 不写**验证不了**的内容 | 读不出来的字段宁可留空，也不猜 |

## 适用场景

- 老项目补文档，让新人 / AI 能接手
- 新项目初始化文档体系
- 团队统一文档结构

## 与 `agents-init` 的关系

`agents-init` 只做 AI 工具的入口配置（`AGENTS.md` + 各工具指向文件）。
本技能范围更大：**先调研、再产出架构与接口文档，最后才配入口** —— 因为 `AGENTS.md` 里要指向的那些文档，得先存在。

## 技能内部结构

```
skills/ai-ready/
├── SKILL.md               # 主技能定义 + 详细执行规则
└── README.md              # 本文件
```
